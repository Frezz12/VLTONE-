# VLTONE Forum

Самостоятельный Next.js / TypeScript сайт сообщества: `forum.vltstudio.ru`. Пакет `@vlt/forum` входит в общий pnpm workspace. Go API, PostgreSQL и аккаунты общие с основным сайтом; бизнес-логики и отдельной базы в Next.js нет.

## Локальный запуск

Используйте версии из корневых manifest/lockfile: Node 24, pnpm 11.3.0, Go 1.26.7. Установите FFmpeg с encoders `libx264`, `aac`, `libvpx-vp9`, `libopus` и `mjpeg`. Для desktop нужен libarchive (`brew install libarchive` на macOS; зависимость уже включена в vcpkg).

1. Настройте Go backend по `backend/README.md`, задайте `PUBLIC_ORIGIN=http://localhost:3000`, `FORUM_ORIGIN=http://localhost:3002` и `DESKTOP_API_ORIGIN=http://localhost:8080`.
2. Примените миграции: из `backend/` выполните `go run ./cmd/migrate up`.
3. Запустите `go run ./cmd/api` и отдельным процессом `go run ./cmd/forum-media` с тем же окружением.
4. Из корня выполните `pnpm install --frozen-lockfile`, затем `pnpm dev` (сайт 3000, админка 3001, форум 3002). `VLT_API_ORIGIN=http://localhost:8080` задаёт адрес Go для прокси Next.js.

Без `FORUM_OBJECT_ENDPOINT` используется файловое хранилище под `STORAGE_ROOT/forum`. Секреты S3 и desktop-токены не попадают в Next.js/browser JS. Локальные части загрузок отправляются прямо в Go; в production — напрямую в отдельный приватный S3 bucket. Для cookie-тестов разных сайтов используйте разные hostnames: основной сайт `127.0.0.1`, форум `localhost` (cookies не разделяются по портам).

## Поведение первой версии

Русский/английский интерфейс, темы, адаптивная лента, подписки, профили, сохранённое, уведомления, поиск, разделы/темы/ответы, цитирование, Markdown без HTML. Короткие посты используют существующие статьи с `kind=post`; старые статьи и маршруты остаются совместимыми. Лента использует cursor по дате/UUID, от новых к старым. Лайки, подписки и сохранение имеют идемпотентные PUT/DELETE.

Вход через основной сайт: 60-секундный одноразовый код, точный redirect URI, state и PKCE S256. Каждый сайт получает собственную host-only HttpOnly cookie. Desktop получает отдельную сессию, связанную с устройством; обновление его access token не меняет успешную web-сессию. Выход из приложения/отзыв устройства отзывают связанные сессии. После выхода на форуме кнопка входа во встроенном браузере снова предлагает аккаунт программы.

Публикация доступна немедленно после завершения загрузок. Премодерации, сканирования содержимого и очереди одобрения нет. Лимиты по умолчанию: 10 вложений, изображение 10 000 000 байт, VLT 1 000 000 000 байт, одно видео 250 000 000 байт и 300 секунд. Квота автора — 10 000 000 000 байт, одновременно до 20 незавершённых загрузок. Размерные лимиты и квота настраиваются через `FORUM_*_MAX_BYTES`.

Видео MP4/MOV/WebM публикуется вместе с постом, а PostgreSQL worker отдельно готовит MP4/H.264/AAC, WebM/VP9/Opus и обложку. Не более 1920×1080/30 fps с сохранением пропорций. До готовности доступен оригинал; видео длиннее 300 секунд становится недоступным с сообщением автору. Ошибка не удаляет пост. Задания имеют lease 25 минут, timeout 20 минут и до трёх попыток. Состояние переживает перезапуск; незаконченные выходные объекты учитываются в отдельной таблице и удаляются после истечения lease.

Модерация находится в существующей админке `/forum`: жалобы, скрытие/восстановление, разделы, закрепление/закрытие, принятый ответ. Права `forum.read` / `forum.write`, журнал аудита общий. Скрытый родитель закрывает доступ к дочерним материалам и вложениям. В разделе помощи принятый ответ может отметить автор темы.

## Установка в приложении

Автоустановка разрешена только для стабильного download-маршрута настроенного официального форума. Браузеры Qt Quick и Widgets используют один `ForumBrowserBridge` и `VltContentInstaller`. Метаданные проверяются отдельно, байты сначала попадают во временный каталог; проверяется размер/SHA-256, затем штатный парсер и атомарная запись. Desktop-токены не передаются странице.

| Формат | Библиотека |
| --- | --- |
| `.vltmini` | MiniModules |
| `.vltnode` | CreatorNodes |
| `.vltcreator` | CreatorProjects (диалог открытия Creator) |
| `.vlts` | Channel Strips; `resource_type=offline-strip` — Offline Processing |
| `.vltmorph` | пользовательская библиотека Morph |
| `.vltslicer` | Presets/Slicer (диалог загрузки Slicer) |
| `.vlttheme` | установщик тем, без применения |
| `.vltlang.json` | менеджер языков, без применения; замена только явно |
| `.vlt`, `.vlt.zip` | DownloadedProjects, видны в диалоге открытия |
| `.vltt`, `.vltt.zip` | существующая библиотека шаблонов |

Меню браузера «Package saved project for forum…» упаковывает сохранённую папку проекта/шаблона вместе с манифестом, Content, State и относительными ресурсами. Для несохранённых изменений сначала сохраните проект. ZIP: максимум 4 GB после распаковки, 10 000 записей, 1 GB на файл, глубина 32; ссылки, специальные файлы, traversal, шифрование и коллизии имён запрещены. Парсинг не запускает плагины, Creator-код или проект. Неизвестные расширения остаются обычными загрузками. Установка не меняет текущую сессию, канал, тему или язык.

## Проверки

- `pnpm typecheck`, `pnpm build`, `pnpm generate:api`.
- Из `backend/`: `go test ./...`; реальные PostgreSQL проверки включаются переменной `VLT_TEST_DATABASE_URL`.
- ВНИМАНИЕ: интеграционные тесты удаляют схему указанной базы. Используйте только отдельную временную тестовую БД.
- Полный браузерный сценарий с двумя аккаунтами: `VLT_TEST_PLAYWRIGHT=1 go test ./internal/api -run TestPostgresForumCommunity -count=1 -timeout=10m`. Нужен установленный Playwright Chromium; локальный Chrome можно задать через `PLAYWRIGHT_EXECUTABLE_PATH`. Harness сам запускает API и сайты на 3020/3022.
- `pnpm --filter @vlt/forum test` отдельно проверяет гостевые UI-сценарии.
- Native: `cmake --build build --target forum_content_installer_test browser_navigation_test`; `ctest --test-dir build -R 'forum_content_installer|browser_(quick_)?navigation' --output-on-failure`.

Личные сообщения, группы и синхронизация установок с iPhone не входят в эту версию. Production-развёртывание и проверки реального хранилища/устройств выполняются отдельно по инструкции `packaging/server/README.md`.
