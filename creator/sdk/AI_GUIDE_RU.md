# Контекст для написания C++ в Creator

Этот файл можно передать нейросети перед заданием. Он описывает фактический Creator SDK 1 приложения VLTONE, проверенный 4 октября 2026 года. Полный справочник с заголовком SDK и готовыми исходниками: [CREATOR_SDK_RU.md](CREATOR_SDK_RU.md). Краткий контекст не вводит новых функций API.

## Задача автора кода

Пиши переносимый C++23 для ноды C++ Function внутри графа Creator. Результат сборки — `.vltmini`, который исполняется приложением через WebAssembly и локальный WAMR AOT. Компилятор поставляется с приложением. Не создавай JUCE-проект, VST3-класс, DLL, main, processBlock или другой каркас, которого нет в SDK.

Одна нода содержит одну выбранную entry-функцию и может содержать локальные helpers. Несколько нод связываются сигнальными или функциональными портами. Если пользователь просит одну ноду, не создавай несколько нод без необходимости. Если нужна память, добавь State; это часть одной ноды, а не дополнительная карточка.

## Обязательный контракт кода

1. Полный исходник начинается с `#include <vlt/creator.hpp>`.
2. Entry — одна неперегруженная свободная функция в глобальной области исходника. Рекомендуемое имя `process`; точное имя требуется указать пользователю для поля Entry function. Помечай её `VLT_NODE`.
3. Один вызов получает один аудиокадр/момент времени. Хост сам вызывает функцию внутри блока. Не добавляй в entry цикл обработки массива аудиоблока.
4. Сигнальные аргументы — только `vlt::AudioFrame`, `float`, `bool`, по значению. Возврат — одно из этих значений либо aggregate struct с открытыми полями этих типов.
5. Каждому входу и полю структуры выходов назначай `VLT_PORT("stable_id")`. Сохраняй ID при редактировании существующего кода. Не используй ID `function` или начало `$`.
6. До 16 входов, включая Function, и 1–16 выходов. Отдельный янтарный Function-выход добавляет хост автоматически.
7. `State&` и `const vlt::Context&` — необязательные скрытые аргументы, максимум по одному. Они не являются портами.
8. Внутри вычислений можно использовать double/int/небольшие фиксированные массивы, но не выдавать их наружу как порты.
9. `float amount = 0.5f` задаёт начальное ручное значение входа. Диапазон и единицы из default не выводятся: дай отдельную таблицу параметров и ограничивай значения в коде.
10. Number/Gate без провода используют ручное значение, подключённый провод его заменяет. Аудио и Function требуют подключения для соответствующего использования.
11. Автоматизация приходит с точностью до кадра. Если алгоритму нужно сглаживание, реализуй его явно в State либо укажи ноду Smooth в графе.
12. Entry не должна возвращать ссылку, указатель, void или контейнер STL.

## Точный публичный API

`vlt::AudioFrame` содержит `float left` и `float right`, по умолчанию оба 0. Есть только операторы `AudioFrame * float`, `AudioFrame + AudioFrame`, `AudioFrame - AudioFrame`. Не предполагай наличие `float * AudioFrame`, деления или составных присваиваний.

Функции:

```text
float vlt::clamp(float x, float lo, float hi)
float vlt::tanh(float x)
AudioFrame vlt::tanh(AudioFrame x)
float vlt::sin(float radians)
float vlt::cos(float radians)
float vlt::exp(float x)
float vlt::pow(float x, float y)
float vlt::mix(float a, float b, float t)
AudioFrame vlt::mix(AudioFrame a, AudioFrame b, float t)
```

Mix — линейная формула `a + (b - a) * t`, она не ограничивает t. Clamp требует правильного порядка lo/hi и не лечит NaN. Стандартные `<cmath>`, `<algorithm>`, `<array>`, `<cstdint>` доступны; например, `std::isfinite` и `std::abs`. В SDK нет готовых C++-классов Chorus, Delay, Filter, Oscillator, Parameter или AudioBuffer; эффекты с такими названиями существуют как ноды графа.

`const vlt::Context&`:

```text
double sampleRate        частота в Гц
double tempo             BPM
double beat              PPQ-позиция текущего кадра
int64_t sampleTime       позиция кадра на временной шкале
uint64_t seed            seed модуля
unsigned channels       1 или 2
bool playing            играет ли транспорт
```

Mono-вход зеркалируется в L/R, хост использует левый выход. Для стерео нужны независимые истории L/R. Не возвращай тишину только потому, что playing == false: это может отключить мониторинг или хвост эффекта.

## Состояние и подготовка

DSP-память хранится в пользовательском trivially-copyable State с тривиальным деструктором. Изменяемые global/static/thread_local запрещены. `constexpr`-константы разрешены. Подходят простые поля, AudioFrame, небольшие std::array, vlt::Buffer и vlt::Random.

Необязательные lifecycle-функции имеют точные сигнатуры:

```cpp
void prepare(State& state, vlt::PrepareContext& context);
void reset(State& state);
```

Это объявления формата; в готовом файле приведи определения, если они нужны. PrepareContext содержит sampleRate, channels, maxBlockSize, seed, а также изменяемые автором unsigned latency и tail в сэмплах. Значений ручек в prepare нет: выделяй память под допустимый максимум параметров.

`vlt::Buffer<T>`:

```text
prepare(unsigned count)    выделить и очистить count элементов, только в prepare
size()                     количество элементов
clear()                    обнулить без выделения
operator[](unsigned)       доступ с проверкой границ
```

Нельзя вызывать Buffer.prepare в process/reset. Не заменяй его new, malloc или vector даже в prepare. Не обнуляй весь State с подготовленными Buffer через `state = {}`: потеряются их указатели. Сбрасывай поля и вызывай clear.

Хост перед reset восстанавливает снимок всей подготовленной памяти, затем вызывает reset. Если callback не нужен, его можно не объявлять. Все независимые использования получают отдельные состояния; повторные вызовы через один функциональный аргумент разделяют одну историю.

`vlt::Random` имеет `seed(uint64_t)` и `next()` → float `[0,1)`. Сохраняй генератор в State и инициализируй в prepare из PrepareContext.seed. Не переустанавливай seed на каждом кадре. SeededNoise.cpp показывает воспроизводимый генератор.

Latency — алгоритмическая задержка для компенсации, tail — остаток после окончания входа, оба в сэмплах. Художественная задержка echo/chorus не автоматически равна latency; при непосредственном dry-пути у наших примеров latency 0. Для вложенных Function-вызовов родитель объявляет метаданные всей своей обработки сам.

## Несколько функций

Локальные helpers в том же исходнике вызываются обычным C++. Одна функция становится entry по выбранному имени. Не рассчитывай на прямой доступ к именам или глобальным переменным соседних нод: исходники разделены областями имён.

Для вызова другой ноды добавь вход вида:

```cpp
// Фрагмент списка аргументов entry.
VLT_PORT("saturate")
vlt::Function<vlt::AudioFrame(vlt::AudioFrame, float)> saturate = {}
```

В теле вызывай `saturate(input, drive)`. Свяжи янтарный выход дочерней ноды `function` с этим янтарным входом. `= {}` является заготовкой, а не допустимой вызываемой функцией без связи.

В Function-сигнатуре перечисляются только обычные сигнальные аргументы и результат дочерней функции. State и Context передаст хост. Собственные Function-зависимости дочерней ноды соединяются в графе и в эту сигнатуру не включаются. Входами Function нельзя передавать ещё один Function как обычный аргумент вызова.

Аргументы берутся из строки вызова, не из ручек и аудиопроводов дочерней карточки. Последние относятся только к её отдельной сигнальной обработке. Helper, используемый исключительно как вызываемая функция, не требует отдельного Audio-провода к своим обычным входам.

Разные Function-входы независимы по State, даже если получают один источник. Несколько вызовов через один вход используют одно State. Для разных фильтраций используй два Function-аргумента; для обработки стерео — AudioFrame и независимые L/R-поля либо отдельные привязки.

Структура с несколькими результатами передаётся через Function как соответствующий aggregate-тип родителя. Типы полей и их порядок должны совпадать. Вызывай один раз, сохраняй результат и читай его поля. Структура из одного поля не эквивалентна одиночному результату.

Функциональные циклы запрещены. Обычные сигнальные циклы тоже запрещены. Create function создаёт и соединяет ноду, но вызов автор размещает сам. Extract function переносит самостоятельный helper с уникальным именем; произвольные локальные зависимости и State автоматическим выносом не поддерживаются.

## Внешний интерфейс и лимиты

В одном модуле максимум две внешние ручки, но у внутренних нод до 16 входов. Внешние ручки создаёт Interface, а не C++-параметры автоматически. Укажи минимум, максимум, единицы, default, шкалу и провода от выходов Interface к параметрам. Один контрол можно развести на несколько входов.

В режиме log минимум обязан быть положительным. Проценты 0–100 и доля 0–1 различаются: явно выбери шкалу и придерживайся её в коде. На Channel Strip максимум три карточки. В графе максимум 64 ноды и 128 связей; до восьми режимов с общими внешними контролами.

До 256 KiB исходника на ноду; до 16 MiB линейной памяти на экземпляр кода; линейный стек 64 KiB. Не используй большие локальные массивы. Экспортируемая latency ограничена 30 секундами, tail — 120 секундами. Вычислительный бюджет ограничен: бесконечные циклы и чрезмерная рекурсия останавливаются с ошибкой.

Нет исключений, RTTI, ОС, файлов, сети, пользовательских потоков, внешних DLL, произвольных include рядом с проектом и общего динамического heap. Нет встроенного AI или MIDI API. В process/reset не должно быть аллокаций, I/O, блокировок и ожидания.

## Формат ответа с готовым решением

Верни:

1. Краткое описание алгоритма и сколько C++-нод он использует.
2. Полный отдельный исходник для каждой ноды, без многоточий и скрытых обязательных файлов. Укажи Entry function каждой.
3. Таблицу входов/выходов со стабильными ID, типами, единицами, диапазонами и default.
4. Таблицу соединений `источник.порта → получатель.порта` с пометкой Audio/Number/Gate/Function.
5. Настройки максимум двух внешних регуляторов Interface.
6. Как устроены State, prepare/reset, latency/tail и mono/stereo.
7. Короткую инструкцию: импорт/вставка, Обновить ноду, связи, Save, Compile, выбор в MINI.
8. Что реально проверено и что требует теста. Не заявляй сборку или прослушивание, если их не выполнял.

После любого изменения исходника требуется «Обновить ноду», затем Compile. При изменении существующего решения сохраняй ID модуля, внешних контролов и портов. Перестановку однотипных аргументов Function обязательно согласуй с местами вызова: одни аннотации не меняют позиционный вызов C++.
