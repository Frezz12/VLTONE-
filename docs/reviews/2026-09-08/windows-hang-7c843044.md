## Подтверждённый дефект и изменения

`RecoveryJournal::run` увеличивал счётчик живости в собственном рабочем потоке.
`daw_guard` считал этот счётчик доказательством отзывчивости приложения.
Поэтому зависший UI с продолжающим работать журналом оставался незамеченным.

Добавлен отдельный UI heartbeat, который подтверждается из UI-таймера до
вызовов плагинов и файловых операций. Фоновый счётчик остаётся диагностикой
самого журнала; watchdog предпочитает UI heartbeat в новых сессиях и сохраняет
совместимость со старыми файлами.

Вердикт watchdog хранится в принадлежащем ему `watchdog.json`: worker больше
не может стереть отметку о зависании очередной записью `session.json`.
Чтение сессии учитывает только вердикт для её идентификатора времени старта
и текущего UI heartbeat; возобновление UI снимает временную отметку.

На Windows guard удерживает дескриптор наблюдаемого процесса и считывает его
код после завершения. При обнаружении зависания создаётся локальный
`hang.dmp` с потоками и стеками, без полного снимка памяти. Результат записи
дампа и код ошибки сохраняются в sidecar. Дамп автоматически не отправляется.
Снимок выполняется из отдельного guard-процесса согласно рекомендации
[MiniDumpWriteDump](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/nf-minidumpapiset-minidumpwritedump).
Код завершения хранится как код процесса и не выдаётся за доказанное SEH-исключение:
[GetExitCodeProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getexitcodeprocess).

Репортёр включает сведения watchdog в текстовый артефакт, сохраняет причину
зависания при пустом crash marker и отдаёт приоритет реальному маркеру исключения.
Recovery-статистика теперь получает реальные счётчики xrun из контроллера.

- Собраны приложение, guard, reporter и оба теста.
