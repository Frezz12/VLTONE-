# Исправления аудиоэкспорта — 8 сентября 2026

Исправлены пять дефектов из [ревью рендера](audio-render-review.md). Изменения находятся в рабочем дереве; приложение собрано в `build/bin/VLTONE` на macOS arm64, RelWithDebInfo. Установленная версия приложения не заменялась.

Последующая корректировка обработки restart при экспорте описана в [отдельном отчёте](audio-export-reconfiguration-fix.md): служебные VST3-уведомления обслуживаются без сброса DSP, настоящая перенастройка допускает повторный проход.

## Что изменилось

1. **Ошибки DSP доходят до экспорта.** Адаптеры CLAP, VST3 и AU возвращают отдельный результат ошибки обработки. После завершения блока движок проверяет его до передачи аудио в файл. Ошибка плагина или планировщика завершает проход; транзакция удаляет временные файлы и сохраняет предыдущие результаты. Диагностика плагина содержит имя узла, его ID и позицию блока в сэмплах. Допустимая тишина и CLAP sleep остаются успешными результатами.

2. **Компенсация задержек рассчитывается после offline-подготовки.** После восстановления состояния клона выполняются активация в окончательном режиме, обслуживание отложенной подготовки и компиляция задержек всех ветвей. Только затем рассчитываются предзапуск, обрезка и длина файлов. Подготовка допускает до восьми попыток стабилизации при запросах restart/latency. Для общего `RealtimeEngine::renderOffline` после прохода также заново компилируется realtime-граф с его собственными задержками.

3. **Потерянные или неактивные плагины больше не пропускаются молча.** Перед записью сверяются включённые слоты модели с созданными экземплярами: инструменты, channel/master inserts, sampler FX, clip FX и обе стороны dual mono. Отказ CLAP принять offline-режим или требование аппаратного realtime теперь приводят к ошибке. Явный bypass и mix=0 разрешают сухой экспорт. Неактивный экземпляр не получает `reset`, требующий активного состояния.

4. **Stems выровнены по фактической задержке каждого tap.** Захваченные копии доводятся до общей точки задержки перед обрезкой файлов. Это не меняет сигнал, который идёт в мастер. При необходимости мастер тоже получает задержку захвата. Завершение хвоста по тишине учитывает выбранные stems, чтобы тихий мастер не обрезал ещё звучащую дорожку. Последний блок источников разделяется точно по границе диапазона.

5. **Offline-экземпляры получают свои callbacks.** Запросы обслуживаются на управляющем потоке после завершения работы аудиопотоков, независимо от UI progress. Изменение latency, restart или reload во время записи файла завершает экспорт с явной ошибкой: продолжать с прежними задержками нельзя. Бесконечный restart при подготовке ограничен числом попыток. Обслуживание между блоками добавлено только в offline-проход.

## Проверки

Добавлены `tests/render_integrity_test.cpp` и загружаемый CLAP-модуль `tests/fixtures/test_clap/TestRenderClapPlugin.cpp` с управляемыми отказами. Тесты проходят через настоящий хост, экспортируют Float32 WAV и повторно декодируют результат.

- Offline-задержка 24 сэмпла, отложенная подготовка с restart и callback во время прохода: смесь совпадает с эталоном по каждому сэмплу с допуском `1e-6`.
- Восемь сценариев отказа, включая DSP, создание клона и правую сторону dual mono: ошибка вместо успешного файла, сохранение предыдущего результата, отсутствие временных файлов, возможность повторного экспорта с явно включённым bypass.
- Разная задержка дорожек и дополнительная задержка мастер-плагина: сумма stems совпадает с mixdown по каждому сэмплу при буферах 8, 64 и 512, включая границы произвольного диапазона, pre-roll, mono и stereo. Мастер в этом тесте меняет только задержку; нелинейная общая обработка закономерно может нарушать равенство суммы stems и mixdown.
- Общий движок после успешного прохода и отказа активации возвращается к realtime-задержке и корректному воспроизведению.
- Фикстура проверяет поток выполнения callback и запрещает reset неактивного экземпляра.

Итоговый прогон: **12/12 тестов успешно, 17,35 секунды**:

```sh
ctest --test-dir build -R '^(render_integrity_test|render_test|render_safety_test|processing_render_test|plugin_host_test|engine_graph_test|plugin_insert_test|plugin_midi_test|plugin_vst3_test|plugin_au_test|audio_realtime_test|sampler_test)$' --output-on-failure
```

Приложение и перечисленные цели собраны; `git diff --check` проходит. Исторический `run-render-review.py` сохранён как воспроизведение поведения до исправлений; для проверки исправленного поведения используется `render_integrity_test`.

## Границы результата

Эти проверки подтверждают устранение пяти дефектов движка. Проект и цепочка эффектов пользователя, сообщившего о просадках, не предоставлены, поэтому причина именно его файла пока не установлена. Windows и его сторонние плагины здесь не запускались. Ошибку внутри стороннего DSP исправления не устраняют: теперь такой результат не выдаётся за успешный экспорт.
