# Исправления прокрутки таймлайна

Реализация по [ревью](timeline-scroll-review.md). Изменения внесены после разрешения пользователя; исходные измерения ревью сохранены отдельно. Чужие незакоммиченные изменения рабочего дерева не откатывались.

В изолированном тесте восьми waveform при DPR 2 медиана этапа рисования уменьшилась с 78,967 до 2,580 мс. В последнем совместном тесте записи и прокрутки при буфере 32, DPR 2, p95 paint — 8,921 мс. Прошли сборка, 9 основных CTest, проверки навигации/pattern/editor и зарегистрированный audio-scroll тест. Однако строгий порог p95 16,67 мс не проходит стабильно во всех повторах: в финальной полной матрице прошли 15 из 16 сочетаний. Это измерения тестового проекта, не пользовательского устройства.

## Что изменено

| Пункт ревью | Исправление |
|---|---|
| 1. Повторная растеризация waveform | Вместо QPainterPath используются растровые тайлы по 256 физических пикселей, привязанные к исходному аудио. LRU ограничен 64 МиБ и 2048 тайлами; ключ учитывает источник, обрезку, масштаб, gain, высоту, DPR, цвет и реверс. При целочисленной горизонтальной прокрутке переносится готовая статическая подложка; заново рисуются края и линейка. Дробное движение рисуется напрямую, без накопления размытия. |
| 2. Перерисовка существующих клипов во время записи | Живая запись вынесена из статического слоя в overlay. Кадры записи восстанавливают готовую подложку. Завершённые участки живой волны кэшируются, текущий хвост обновляется. |
| 3. Все старые loop-проходы каждый кадр | Preview вычисляется арифметически и содержит максимум два видимых участка: текущий проход и неперекрытый хвост предыдущего. Полное число проходов хранится отдельно; при Stop сохраняются все реальные takes. |
| 4. Follow мешает ручной прокрутке | Ручная горизонтальная навигация приостанавливает Follow до явного центрирования, повторного включения Follow или нового запуска транспорта. |
| 5. Полный перебор нот в pattern overview | Источники группируются по контейнеру и кэшируются с версиями структуры/геометрии/документа. Границы высоты и видимые ноты берутся из MidiPreviewIndex. |
| 6. Невидимые comp-строки и повторные поиски | Невидимые строки отсекаются до рисования; сегменты группируются по take за один проход. Поиск take в собранном comp использует таблицу, а не линейный поиск для каждого сегмента. |
| 7. Избыточные пробуждения audio helpers | Начальный wake ограничен числом реально готовых корней, числом задач после fusion и размером пула. Поздние разветвления продолжают будить helpers. Сохранены realtime-приоритет, ёмкость пула и прежний бюджет ожидания: агрессивное сокращение ожидания не показало устойчивого снижения CPU. |
| 8. Двойной clock микшера | Во время playback/recording измерители обновляет FrameTimer микшера. Медленный опрос MainWindow только согласует запуск/остановку этого таймера. |
| 9. Потерянные/растянутые транзиенты | Recorder публикует timestamped peak buckets примерно по 25 мс из реально записываемых сэмплов. UI забирает историю, а не последний блок. |
| 10. Неверный канал живой волны | Peaks формируются после выбора каналов конкретного capture: mono не захватывает соседний вход, Inputs 3+ поддерживаются. |
| 11. Data race при смене входа | First channel, channel count и enabled публикуются одним lock-free atomic uint64 и принимаются один раз на границе блока. Ширина открытого WAV сохраняется. |
| 12. No Input не выключает запись | Отключение входа передаётся recorder и input node мониторинга. Повторное включение возобновляет сигнал в той же записи. Отключённый вход больше не блокирует smart monitoring другой дорожки. |
| 13. Нет проверки audio-scroll | Добавлены waveform_paint_test, recording_preview_test и --audio-scroll-check: восемь WAV-дорожек, настоящий путь device callback/graph/recorder, одновременно прокрутка и запись, буферы 32/64/128/512, DPR 1/2. Измеряются paint, интервалы кадров и длительность callback. |
| 14. Метрика скрывает долгие зависания | Интервалы ≥250 мс сохраняются и попадают в frame.stall.ms. Скрытие/остановка clock сбрасывает временную базу. Добавлены input-to-paint-start/end и измерения переноса/рисования статического слоя. |
| Дополнительно: ожидания raster-пула Qt | Профиль показал синхронные ожидания helpers внутри QPainter. На macOS отдельный GUI-пул Qt отключается до QApplication; типичное время paint в сравнении уменьшилось примерно на 15–25%. Для диагностики прежнего поведения есть VLT_QT_GUI_THREADPOOL=1. Это устраняет конкретный путь ожидания, но не все редкие задержки. |

Дополнительно убраны повторные заливки непрозрачного фона, раздельно обрабатываются непересекающиеся dirty-прямоугольники. Округление координат теперь одинаково по обе стороны нуля: клип не получает лишний пиксель смещения при пересечении левого края viewport.

## Проверка

Проверки и замеры запускаются последовательно, без одновременной сборки. Рабочая конфигурация: macOS arm64, Qt 6.11.2, RelWithDebInfo.

- Recorder: матрица 32/64/128/512; транзиент остаётся в preview после двух секунд без чтения UI; mono Input 3 не смешивается с соседями; конкурентная смена маршрута не меняет пару каналов внутри блока; No Input работает через controller и настоящий callback.
- Loop: 302 записанных прохода занимают максимум два preview-span, сохраняют смещение внутри capture и полностью приземляются в takes.
- Renderer: cached/uncached сравниваются попиксельно; проверяются gain, реверс, дробная прокрутка, DPR, отсутствие швов, рост видимого хвоста записи, смена источника и лимит памяти.
- Статическая подложка: результат переноса попиксельно совпадает с полной перерисовкой, включая разворот движения, дробные координаты и скруглённые края.
- FrameClock: искусственная блокировка GUI на 320 мс остаётся в метриках; скрытое окно не создаёт ложного stall при возвращении.
- Audio graph: compact slow-root/fan-out проверяется при 32/64/128/512; сохраняется параллелизм тяжёлых стадий и результат рендера.

Числа итогового прогона и команды находятся в [evidence](timeline-scroll-fixes-evidence/README.md).

## Границы результата

Это проверка кода и воспроизводимого проекта из WAV, без открытия пользовательского аудиоустройства и сторонних плагинов. В совместном тесте используются realtime-регистрация вызывающего потока и helpers, но нет device workgroup. Превышение времени callback в таком тесте — диагностическая величина, а не аппаратный xrun.

25-миллисекундная история recorder ограничена 8192 buckets — примерно 205 секундами. Если UI не обслуживается дольше, старые непрочитанные пики не восстанавливаются из этой истории; сам WAV пишется независимо. Envelope UI также ограничен и при длительной записи укрупняет buckets с сохранением максимума.

Paint completion и interval не равны моменту представления кадра дисплеем. В evidence сохранены p50/p95/p99/max, включая редкие длинные кадры: измерения не дают гарантии нулевых задержек на любом устройстве при произвольной нагрузке.

Редкие задержки GUI всё ещё зарегистрированы на стенде. После отключения raster-пула Qt кадр 55,432 мс занял 11,319 мс CPU GUI при нулевом приросте page-ins процесса. Конкретный источник остальных ожиданий или вытеснения не установлен; устранение этого остаточного эффекта не заявляется. В последнем повторе один callback при буфере 32 занял 0,740 мс при сроке 0,667 мс. Поэтому отсутствие любых просрочек аудио тоже не заявляется. Подробные замеры, включая неуспешные серии, ограничения и команды воспроизведения сохранены в evidence.
