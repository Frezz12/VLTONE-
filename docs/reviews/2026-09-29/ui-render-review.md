# Ревью отрисовки и отзывчивости интерфейса

Проверены Qt Widgets/QPainter → GPU SceneRecorder/Qt Quick, изменение размеров панелей, слои native-редакторов, закрытие/отмена открытия плагинов, обновление волн, фоновая обработка семплов и общие обработчики ввода. Изменения других незавершённых задач в рабочем дереве сохранены.

## Подтверждённые проблемы и исправления

| До | После | Причина / затронутый код |
| --- | --- | --- |
| Непрозрачное основное окно использовало прозрачную поверхность GPU | Фон берётся из палитры окна и обновляется вместе с темой; прозрачность остаётся у действительно прозрачных окон | `app/graphics/WorkspaceSurface.cpp`: при изменении размеров могли просвечивать backing store и native-соседи |
| Изменение размера workspace очищало весь кэш виджетов | Перезаписываются изменившиеся поверхности; кэш остальных сохраняется | `WorkspaceSurface::resizeSurface` |
| При первом появлении native GPU-поверхности Qt мог оставить накопленные обновления обычных контролов необработанными | После события expose возобновляется штатная обработка backing store | `WorkspaceSurface::eventFilter`; воспроизведено с `AA_DontCreateNativeWidgetSiblings`, как в приложении |
| После поднятия GPU-окна Qt мог пропустить повторный `raise()` окна плагина | Восстанавливается также реальный native-порядок окон | `WorkspaceSurface::resizeSurface`; недостаточно порядка QObject |
| Растягивание микшера сбрасывало геометрию дорожек таймлайна | Меняется обрезка сохранённой геометрии; изменение содержимого или прокрутки по-прежнему инвалидирует её | `TimelineWidget::setBottomInset`, `paintScene` |
| Изменение ширины браузера пересобирало те же временные фрагменты таймлайна на каждом пикселе | При неизменной высоте переиспользуются фрагменты по 512 px; узкие размеры и переходы через порог по-прежнему инвалидируют кэш | `TimelineWidget::resizeEvent`, `drawStaticFrame`, `paintScene` |
| Разделители игнорировали конечную координату release и могли сохранять прерванный drag | Конечная координата применяется, потеря захвата/скрытие/деактивация завершают жест | `app/Controls.cpp` |
| Встроенную рамку можно было уменьшить ниже минимального размера редактора и обрезать контролы Sampler | Рамка учитывает актуальный минимум содержимого и собственный заголовок; в тесной рабочей области остаётся ограниченной её размерами | `app/InternalEditorFrame.cpp`; учтено также изменение минимума во время жеста |
| Web/AI/Notebook начинали drag от сохранённой ширины, даже если окно уже сжало панель | Начальная ширина берётся с экрана | `app/MainWindow.cpp` |
| Закрытие VST3 во время отложенного открытия оставляло пробный GUI | Освобождается также ещё не подключённый `IPlugView` | `PluginEditorWindow::detachFromPlugin`, `Vst3Instance::closeEditor` |
| Каждый редактор с sidechain пересчитывал граф маршрутизации каждые 200 мс | Доступные маршруты проверяются при открытии списка; в заголовке обновляются только выбранные имена | `app/PluginEditorWindow.cpp` |
| Фильтр редактора обходил иерархию виджетов на каждом paint/move, включая скрытые редакторы | Фильтр устанавливается только для видимого редактора и сразу отбрасывает ненужные типы событий | `PluginEditorWindow::eventFilter`, `showEvent`, `hideEvent` |
| Поворот Boost запускал полный пересчёт аудио и пиков в UI-потоке | Обработка выполняется существующим ограниченным фоновым исполнителем; результат публикуется после проверки актуальности | `controller/EngineController.cpp` |
| Gain/Pan/Fade во время пересчёта Boost могли снова запустить обработку синхронно | Живое размещение использует последнее готовое аудио до публикации результата | `EngineController::processedClipSample` |
| Переход редактора на чтение готового кэша оставлял волну пустой при холодном исходнике offline-клипа | Отдельный запрос готовит исходник в фоне, сохраняя offline-обработку и состояние freeze | `EngineController::requestClipSampleData`, `pumpDeferredClipSync`; проверка совместимости нового пути |
| Таймлайн переключался между обработанной и исходной волной, семплер очищал пики на время пересчёта | Последняя готовая волна сохраняется до готовности следующей | `EngineController::clipWaveform`, `app/SamplerPanel.cpp` |
| GPU-кэш семплера мог не заметить готовые пики того же размера | Версия кэша меняется при публикации новых пиков | `SamplerWaveform::paintScene`, `requestPeakBuild` |
| Во время пересчёта Reverb старые пики могли отображаться с новой длиной аудио | Пики и масштаб маркеров меняются вместе | `SamplerWaveform::m_peakSample` |
| Появление новой волны могло совпасть с переиспользованием статического кадра таймлайна | Завершённый пересчёт явно инвалидирует статический кадр | `TimelineWidget::refreshClipWaveforms` |
| Каждый шаг Boost заново считал длительность проекта и инвалидировал геометрию | Это делается только при фактическом изменении длительности клипа | `EngineController::setClipSampleParameter` |

GPU Render включён по умолчанию в настройках и выборе backend. Явно сохранённое отключение и диагностический override сохраняют приоритет. Совместимый renderer остаётся доступным.

Обычный путь закрытия уже открытого VST/VST3/CLAP-редактора освобождал GUI корректно. Найдена конкретная утечка при отмене открытия VST3 и отдельная ошибка порядка native/GPU-слоёв. Сам аудиоплагин после закрытия GUI должен продолжать работать в проекте.

## Проверки

Release-сборка приложения и затронутых тестов завершена успешно. Полный `--uiperfcheck` прошёл 67 проверок, включая прерывание жестов, привязку zoom/pan, сетку при 100/150/200%, виртуализацию 500 дорожек и микшера, субпиксельный playhead и сохранение статического кадра.

Отдельно прошли проверки семплера, редакторов, отмены открытия VST3 и фоновой подготовки исходников. Аппаратный D3D11/threaded-набор прошёл при масштабе Windows 100%, 150% и 200%; проверены также программный fallback и приоритет сохранённых настроек GPU.

Четыре сценария перетаскивания на 500 дорожках прошли с GPU, выбранным по умолчанию. При движении Sampler/native-редактора таймлайн не перестраивался; при изменении высоты микшера и ширины браузера число повторных построений фрагментов дорожек — **0**. После изменения размеров сохранённое изображение совпало с принудительной полной перерисовкой; для ширины проверены также переходы через порог 512 px.

Итоговый прогон с обычной темой приложения, p95 в миллисекундах:

| Сценарий | Обработка ввода | Подготовка сцены | Интервал отправки кадров |
| --- | ---: | ---: | ---: |
| Перемещение Sampler | 0,11 | 2,56 | 6,11 |
| Перемещение native-редактора | 1,15 | 3,04 | 11,26 |
| Высота микшера | 0,75 | 4,17 | 12,16 |
| Ширина браузера | 4,59 | 6,48 | 20,46 |

Интервал отправки кадров не равен задержке от мыши до физического показа на экране. Это единичные диагностические прогоны, не гарантия FPS. Ранние baseline-файлы создавались до исправления применения темы и размера редактора в тестовом запуске; их нельзя считать строгим сравнением итогового интерфейса «до/после».

В самих проверках исправлены устаревшее предположение о первом пункте меню Piano Roll, неверное ожидание пустого кэша у frozen-проекта и учёт одного пограничного пикселя при субпиксельном playhead. Белый Inspector в раннем контрольном снимке воспроизводился и с CPU: тест создавал окно до применения темы. Теперь тест применяет тему и проверяет цвет фона по пикселям; production-код инспектора не менялся.

В последнем общем CTest-прогоне прошли 34 из 35 тестов. CPU-тест прокрутки аудио один раз превысил порог p95 (51,925 мс при лимите 50 мс); отдельный повтор без параллельного просмотра снимков прошёл. Таким образом, все 35 выбранных тестов получили успешный результат, но общий прогон не был полностью зелёным — чувствительность этого нагрузочного теста к условиям запуска зафиксирована. Порог не изменялся.

Browser resize дополнительно прошёл при 150% и 200%: ноль повторных построений фрагментов во время жеста, совпадение с полной перерисовкой в восьми контрольных ширинах и корректный фон инспектора. `git diff --check` для изменённых файлов чистый.

После последней правки минимального размера редакторов повторно прошли все 7 связанных CTest-проверок и `--editorcheck`. Новая регрессия проверяет уменьшение настоящим жестом до минимума содержимого, изменение этого минимума во время жеста и сохранение доступного заголовка в маленькой рабочей области.

Команды, JSON-профили, снимки и журналы находятся в `artifacts/ui-render-review/` и `artifacts/ui-gpu-review/`. Основные журналы: `build-final.log`, `tests-final.log`, `audio-scroll-final.log`, `scaling-final.log`, `motion-final.log`, `browser-dpi-final.log`, `editors-final.log`. Собранное приложение: `build-windows/bin/VLTONE.exe`.

## Границы проверки

Аппаратные проверки выполняются на Windows / Qt 6.8.3 / Direct3D 11. Нагрузочный проект содержит 500 дорожек и 19 960 MIDI-клипов; native-редактор в нём — детерминированный тестовый host, а не конкретный сторонний синтезатор. Это не измерение Hive на пользовательском проекте и не подтверждение отсутствия ошибок во всех сторонних плагинах, на macOS или на других видеодрайверах.
