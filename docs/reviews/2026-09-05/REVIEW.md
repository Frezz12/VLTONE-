1. **[P1] Вложенный RenderGate преждевременно открывает аудиопоток. Воспроизведено.**

   Место: [RealtimeEngine.cpp:11](/Users/nikolay/Documents/code/VLTONE/VLTONE-/engine/Engine/RealtimeEngine.cpp:11), особенно деструктор на строке 18. Каждый экземпляр пишет один общий bool; уничтожение внутреннего экземпляра записывает `false`, хотя внешний ещё существует. `renderOffline()` держит внешний gate на весь проход. Вызванный из progress callback `pumpPluginEvents()` может создать внутренний gate при reload/reconfigure плагина. После него живой callback снова допускается в тот же GraphProcessor и те же mutable DSP-буферы.

   Проверка `gate_probe.cpp`: до внутреннего gate число вызовов live DSP равно 0; после его уничтожения, при ещё живом внешнем gate, равно 1. Нужен gate с корректной вложенностью и единым владением live/offline исполнением. Тест должен проверять не только последовательный запрет, но и одновременные callback/экспорт/переконфигурацию.

4. **[P1] Весь исходный PCM хранится в RAM; смена частоты экспорта пересоздаёт его синхронно. Измерено.**

   Места: [AudioFileDecoder.cpp:91](/Users/nikolay/Documents/code/VLTONE/VLTONE-/core/platform/AudioFileDecoder.cpp:91), [EngineController.cpp:1360](/Users/nikolay/Documents/code/VLTONE/VLTONE-/controller/EngineController.cpp:1360), [EngineControllerRender.cpp:568](/Users/nikolay/Documents/code/VLTONE/VLTONE-/controller/EngineControllerRender.cpp:568). Декодер выделяет полный interleaved массив; затем создаётся полный planar массив. Живые клипы удерживают PCM, поэтому `pruneDecodedSampleCache()` не ограничивает память большого проекта. При смене частоты очищаются кеши, весь материал снова декодируется, строятся peaks, производится ресемплинг; после экспорта исходная частота восстанавливается с очередной пересборкой. Старые буферы некоторое время удерживаются опубликованными снимками.

   В проверке с 8 уникальными stereo-файлами по 30 секунд, 48 кГц, блок 64, экспортом диапазона 0,1 секунды и отменой на первом callback: при 48 кГц первый callback через 0,35 мс, полный вызов 0,47 мс, process peak RSS 118 MiB; при 96 кГц — 959,95 мс, 1009,35 мс, peak RSS 316 MiB. Это одиночные измерения на данной машине, не норматив производительности. До первого callback прогресс и отмена не обслуживаются. Только PCM 64 уникальных stereo-дорожек по 10 минут при 48 кГц занимает около 13,73 GiB без временных копий, плагинов и истории. При нехватке RAM возможны swap и аварийный выход: граница диалога не переводит `std::bad_alloc` в результат ошибки.

   Нужны блочное чтение длинных файлов, ограничение кешей по байтам, отдельное преобразование частоты для offline-сессии и отменяемая подготовка. [Sampler KeepOnDisk:300](/Users/nikolay/Documents/code/VLTONE/VLTONE-/plugins/Internal/SamplerInstance.cpp:300) сейчас лишь пропускает precompute и продолжает использовать `request.raw`; это не дисковый streaming. Нельзя рассчитывать, что этот переключатель устранит нехватку памяти.
