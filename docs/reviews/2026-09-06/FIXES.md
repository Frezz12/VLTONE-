# Исправления по ревью производительности и зависаний

Внесены изменения по 14 пунктам [исходного ревью](/Users/nikolay/Documents/code/VLTONE/VLTONE-/docs/reviews/2026-09-05/REVIEW.md). Исходный отчёт описывает состояние кода до исправлений; приведённые в нём номера строк относятся к той версии.

| № | Исправление |
|---|---|
| 1 | `RenderGate` учитывает вложенность и сериализует управляющие потоки. Вложенный guard не открывает аудиопоток. Повторная подготовка/публикация во время прохода отклоняется; ошибки подготовки охвачены восстановлением. |
| 2 | Экспорт создаёт отдельный контроллер с копией документа, собственными экземплярами плагинов, графом и планировщиком. Общими остаются неизменяемые аудиоданные. Обработка событий прогресса больше не меняет граф экспорта. Bounce проверяет ревизию документа после обработки событий. |
| 3 | Экспорт использует модальность диалога вместо отключения родительского окна, которое отключало и Cancel. |
| 4 | Добавлена загрузка PCM блоками по 8192 кадра, проверка размеров и отмена между блоками. Большие буферы и промежуточные данные эффектов используют файловое отображение. Маленькие PCM-буферы делят бюджет heap 64 MiB. Исходная частота сохраняется в отдельном кэше; экспорт не пересобирает обратно рабочую сессию. Пересчёт частоты сохраняет sinc-фильтр и допускает отмену. Общий кэш со слабыми ссылками разделяет исходники клипов, семплеров и предпрослушивания. Подготовка отложенных изменений и ожидание расчётов семплера в контроллере экспорта обслуживают прогресс и отмену. |
| 5 | Чтение/запись состояния работающих плагинов в загрузке проекта, сохранении, recovery и копировании цепочки защищены `RenderGate`. Глобальный декодер семплера защищён при смене/чтении функции. |
| 6 | Старый манифест удаляется только после проверки `filesystem::equivalent`: регистровый псевдоним нового файла сохраняется. |
| 7 | Файлы пишутся во временные имена. Каждый готовый файл публикуется атомарным переименованием; ошибка/отмена очищает только файлы текущей задачи. Диалог выбирает свободное имя; старый API с точным путём атомарно заменяет готовый файл и запрещает замену исходного аудио проекта. |
| 8 | Квадратичная матрица предков заменена передачей свободных буферов вдоль зависимостей, с линейным объёмом служебных данных. Повторное использование консервативно для разветвлений и безопасно при параллельном DSP. Проверка повторного соединения избегает линейного поиска по огромному входному списку мастер-шины в обычном случае. |
| 9 | Массовая синхронизация строит один индекс активных automation-клипов по целевому каналу. Он живёт только во время операции, поэтому не хранит устаревших указателей после редактирования документа. |
| 10 | Прогресс учитывает предварительный проход и показывает подготовку/прогрев/запись. В Bounce добавлена длительность прогрева, включая прежний режим «с начала проекта». Для материала без работающих плагинов прогрев пропускается. Обновления интерфейса ограничены примерно 30 разами в секунду. |
| 11 | Рисование и hit-test таймлайна используют кэш проверенного пути и длины. Проверка файлов остаётся в управляющем пути подготовки воспроизведения. |
| 12 | PreviewLoader держит один рабочий запрос и последнюю ожидающую цель. Устаревшее декодирование и расчёт огибающей останавливаются между блоками; исключения не выходят из рабочего потока. |
| 13 | Копии UndoStack разделяют неизменяемые действия; полные снимки захватываются через shared_ptr. Введён оценочный бюджет снимков 128 MiB с сохранением последнего действия; группы учитывают суммарный размер. Копии WaveformCache разделяют огибающие. |
| 14 | Загрузчик проверяет строковый тип `format` и возвращает ошибку для повреждённого документа вместо исключения JSON. |

Дополнительно исправлена сборка приложения с `DAW_ENABLE_COLLABORATION=OFF`: режимы создания скриншотов больше не ссылаются на методы отключённых облачных диалогов. Новые сообщения прогресса и настройка прогрева переведены на русский.

## Границы проверки

Файловое хранение PCM требует свободного места во временном каталоге; страницы отображений могут присутствовать в RSS и освобождаются ОС при давлении на память. Бюджет heap не является лимитом всей памяти приложения: плагины, огибающие, граф, документ и системный файловый кэш учитываются отдельно. Для очень большого одиночного снимка Undo сохраняется последнее действие даже сверх оценочного бюджета.

Сторонние плагины продолжают работать внутри процесса. Зависший или аварийный вызов внутри самого плагина нельзя прервать проверкой Cancel между блоками; изоляция графа не является изоляцией процесса. Реальный большой проект, на котором наблюдалось зависание, в этой проверке не воспроизводился. Проверки выполняются на macOS; ветки Windows/Linux требуют запуска их CI.
