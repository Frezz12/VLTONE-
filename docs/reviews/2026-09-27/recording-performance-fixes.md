# Исправления производительности записи — 27 сентября 2026

Продолжение [аудита записи и Auto Strip Silence](D:/Code/DAW/docs/reviews/2026-09-27/recording-performance.md). Это первый набор исправлений: лишняя обработка Clip FX во время следующего дубля, повторная подготовка записи при Stop, публикация результатов Auto и перерисовка таймлайна.

## Что изменено

1. **Старые Clip FX исключаются из исполняемого графа записываемой дорожки.** Экземпляры плагинов сохраняются, поэтому открытый редактор и настройки продолжают относиться к тому же объекту. После публикации графа короткий RenderGate дожидается завершения предыдущего блока. Деактивация плагинов выполняется уже после освобождения gate, когда текущий граф их не использует. При возвращении цепочки выполняется штатная активация: старый поток DSP не остаётся замороженным на время дубля. Добавление эффектов во время записи также создаёт экземпляр, но не включает его в обработку.

2. **Auto применяется ко всем записанным дорожкам перед общей публикацией графа.** Число пересборок при Stop больше не растёт с числом дорожек: одна завершает capture, вторая публикует размещённый и обработанный материал. Сохранение Clip FX ограничено прежними клипами, пересекающими записанные интервалы; повторное сохранение внутри Strip Silence убрано.

3. **Новые экземпляры Clip FX получают сохранённое состояние до активации и публикации.** Долгое восстановление всех состояний под общим RenderGate заменено восстановлением только новых экземпляров вне работающего графа. Переиспользуемые экземпляры сохраняют текущее состояние. Undo/Redo использует тот же путь. Если восстановление фрагментов при Auto завершается ошибкой, остаётся запись без очистки, а ошибка показывается пользователю. Сохранение состояния уже работающего плагина по-прежнему требует gate.

4. **WAV после записи декодируется один раз для PCM и waveform.** Раньше предварительный запрос peaks не удерживал декодированные сэмплы, и последующее построение графа могло прочитать файл ещё раз. Размещение записи теперь использует общий кэш `loadSamples()`. Сильные ссылки на PCM всех записанных дорожек сохраняются до публикации общего графа: загрузка следующей дорожки больше не вытесняет уже подготовленную запись.

5. **Undo записи хранит один общий снимок before/after и учитывает его размер.** Два callback больше не захватывают независимые копии одних и тех же моделей. В лимит Undo передаётся оценка объёма снимков вместо стандартных 256 байт.

| До | После | Зачем |
|---|---|---|
| На каждом кадре записи обновляется вся ширина дорожки | Обновляются видимые границы записываемых фрагментов и раскрытой строки дубля | Сокращается растеризация пустого пространства |
| Предыдущая область записи также нуждается в очистке после loop/scroll/Stop | Новая область объединяется с предыдущей, затем обрезается viewport | Предыдущая волна и рамка стираются без следов |

Граница записи и пульсация продолжают обновляться на каждом кадре. Данные MIDI preview уже передаются через `std::span`; дополнительной копии списка нот в этом пути не было.

Регрессионные проверки охватывают исключение и возвращение Clip FX, непрерывный input monitoring, редактирование эффекта во время capture, сохранение настроек, Undo/Redo, реальную запись через callback, многодорожечную Auto-обработку и учёт памяти Undo. Для CLAP/VST3 проверяется сохранение native preset и последующих parameter edits после разделения клипа, Undo/Redo и цикла записи. UI-проверка использует offscreen Qt, DPR 2 и буферы 32/64/128/512.

Приложение `VLTONE.exe` пересобрано. Успешно пройдены 7 функциональных тестов: `plugin_render_state_test`, `strip_silence_test`, `audio_monitoring_regression_test`, `recording_preview_test`, `midi_recording_test`, `clip_library_test`, `processing_render_test`.

UI-тест в общем прогоне один раз не прошёл: в первом сценарии без записи, 32 frames, p95 отрисовки вырос до 108,4 мс. Отдельный повтор `audio_timeline_scroll_test` прошёл во всех восьми сценариях: p95 6,82–7,97 мс, но отдельные кадры всё ещё доходили до 50,94 мс. Это измерение программного harness, а не ASIO xrun.

## Повторные измерения

Те же диагностические программы, 48 кГц, 64 frames, один активный audio worker, без аудиоустройства. Для Stop показана медиана трёх запусков. Во всех финальных прогонах запись завершилась без предупреждений recorder/Auto. Запуски Clip FX, пересёкшиеся с внешней сборкой проекта, помечены в логах и исключены из сравнения; использованы три `verified_round`.

| Показатель | До | После |
|---|---:|---:|
| Узлы графа при следующем дубле поверх 60 фрагментов с EQ | 249 | 8 |
| Среднее время callback в этом сценарии | 5,119 мс | 0,00095–0,00113 мс |
| Stop: 8 дорожек × 60 секунд, Auto выключен | 381,034 мс | 244,525 мс |
| Stop: 8 дорожек × 60 секунд, Auto включён | 497,397 мс | 345,550 мс |
| Пересборки при Stop: 8 дорожек с Auto | 10 | 2 |
| Stop: тихий punch 0,5 с внутри клипа 600 с, Auto включён | 131,269 мс | 128,514 мс |

Callback сравнивается по среднему времени 1000 блоков: исходный запуск до исправления и диапазон трёх запусков после. При обычном воспроизведении эти 60 EQ по-прежнему занимают около 5,15 мс на блок; улучшение относится к следующему дублю на этой дорожке. Нагрузка эффекта дорожки и Master этим изменением не снимается.

Stop восьми дорожек стал быстрее примерно на 36% без Auto и на 31% с Auto. Короткий punch внутри длинного клипа практически не ускорился, что соответствует оставшемуся полному анализу исходника.

## Что остаётся

Stop всё ещё синхронно завершает writer и готовит аудио. Анализ короткого punch внутри длинного исходного клипа всё ещё проходит весь клип. Для устранения этой задержки нужны фоновая подготовка результата и анализ ограниченных интервалов с сохранением семантики hysteresis, padding и grid.

При обычном воспроизведении разнесённые во времени Clip FX всё ещё могут обрабатывать тишину. Их отключение по интервалам требует отдельной поддержки хвостов, прогрева, latency и событий плагинов. Изменение текущего набора относится к дорожкам, которые непосредственно записываются.

Также остаются пики полной перерисовки при скролле. Уменьшенная область обновления записи сохраняет статический кэш и сокращает обновление пустого места, но не устраняет стоимость полной перерисовки viewport при навигации.

Эти проверки не заменяют измерение xrun на реальном ASIO-устройстве со сторонними плагинами.
