# Аудит аудиохостинга — 13 октября 2026

## Область проверки

Проверены адаптеры CLAP, VST3, VST1/2 и Audio Unit, а также общий путь `PluginInstance → PluginNode → GraphProcessor`, обслуживание запросов плагина в `AudioRuntimePluginService`, сканирование, восстановление состояния и офлайн-рендер. Встроенные плагины используют тот же `PluginNode`; отдельный аудит их DSP-алгоритмов в эту работу не входит.

Обработка блока и преобразование событий выполняются без новых выделений памяти: буферы шин, очереди параметров и MIDI-хранилища создаются при активации. Загрузка модулей, пересборка конфигурации и восстановление состояния остаются на управляющей стороне. Платформенные загрузчики и редакторы сохранены отдельными: у них разные правила владения и завершения работы.

## Gullfoss: воспроизведённая причина повторных прерываний

Проверен установленный **обычный Gullfoss VST3**, не Live и не Master:

- файл: `C:\Program Files\Common Files\VST3\Soundtheory\Gullfoss.vst3`;
- UID: `F2AEE70D00DE4F4E536E6454474C4653`;
- сообщаемая задержка при 48 кГц: 947 отсчётов.

При каждой активации Gullfoss вызывает `restartComponent(kLatencyChanged)`. Хост передавал этот вызов одновременно как изменение задержки и как требование перезапуска. `PluginNode::prepare()` уже считывал новую задержку, но запрос перезапуска оставался. Следующее обслуживание плагинов снова останавливало обработку и активировало плагин. Новая активация создавала следующий запрос. Это повторно сбрасывало DSP и буферы компенсации задержки даже при достаточном запасе процессора.

В `Vst3Instance` изменение задержки, объявленное во время текущей активации, теперь обслуживается этой активацией. Соответствующий внутренний флаг подтверждается перед чтением задержки. Уведомления об изменениях после активации и остальные флаги `restartComponent` продолжают обслуживаться. Это также не оставляет старый флаг задержки, который мог блокировать последующее обновление значений параметров редактора.

| Проверка цикла обслуживания | До исправления | После |
| --- | ---: | ---: |
| Повторные активации за 20 циклов | 20 | 0 |
| Готовность плагина | да | да |
| Задержка при 48 кГц | 947 | 947 |

После исправления проверены все девять сочетаний частот **44,1 / 48 / 96 кГц** и буферов **64 / 128 / 512**. В каждом случае: `ready=1`, `reconfigurations=0` за 20 циклов. Задержки: 894 / 947 / 1846 отсчётов соответственно.

Это воспроизведение реального уведомления плагина и цикла обслуживания узла, без аудиоустройства. Оно подтверждает устранение найденного цикла, но не является прослушиванием пользовательского проекта или измерением ASIO/WASAPI underrun.

Логи: [до](../../artifacts/plugin-host-audit-20261013/gullfoss-host-before.txt), [после](../../artifacts/plugin-host-audit-20261013/gullfoss-host-after.txt), [матрица режимов](../../artifacts/plugin-host-audit-20261013/gullfoss-host-matrix.txt).

Все вызовы завершились успешно, сигнал присутствует после стартовой задержки, запросов перезапуска — 0. Медиана `process` — 64,60 мкс, p99 — 86,80 мкс при длительности блока 2666,67 мкс. ## Остальные исправления

| Область | Найденная проблема | Изменение |
| --- | --- | --- |
| VST1/2 | На каждом участке блока между точками автоматизации заново просматривался весь список событий. При плотной автоматизации стоимость обхода росла как произведение количества участков и событий. | MIDI проходит через один курсор на блок. Порядок и смещения событий сохранены; обход линейный. |
| CLAP | Повторная сортировка списка, который уже отсортирован общим узлом и переводится в CLAP без изменения порядка. | Удалена лишняя сортировка в адаптере. |
| CLAP | Каждое выходное событие параметра искало его непрозрачный ID линейно по всем параметрам. | Таблица ID → индекс создаётся при чтении параметров; в callback используется только поиск. |
| VST3 | Отдельные хранилища pitch bend дублировали общий пул точек и добавляли линейный поиск; обновление метаданных могло обращаться к старому MIDI-индексу в новом списке параметров. | Удалён специальный путь. Pitch bend и автоматизация используют уже существующий общий пул. Резервирование очередей вынесено в одну функцию. |
| VST3 | `continousTimeSamples` получал позицию курсора проекта, которая скачет при остановке и перемотке; флаг достоверности непрерывного времени отсутствовал. | Передаётся монотонный `steadyTime`, с `kContTimeValid`, когда время доступно. |
| CLAP / VST3 | Плагин без аудиовыходов вообще не вызывался, даже если должен был обрабатывать события. | Удалён ранний выход. Плагины только с событиями получают `process`. |
| CLAP / VST3 / AU | Блок больше размера, согласованного при активации, выдавался за успешно обработанную тишину. | Возвращается `Error`, чтобы общий путь обработки ошибок мог корректно отреагировать. |
| CLAP | Poly pressure для MIDI-диалекта ошибочно преобразовывался в нативное CLAP note expression. | Для MIDI-порта и явного `preferMidi` используется MIDI poly pressure. |
| VST1/2 / AU | Отсутствующий вход мог использовать scratch, оставшийся после записи плагина в предыдущем блоке. | Запасной вход обнуляется перед повторной передачей; для AU также проверяются номер шины, число буферов и запрошенная длина. |
| AU | CC, pitch bend, channel/poly pressure и program change не доходили до плагина. | Используется общий MIDI-кодек с передачей смещения события в `MusicDeviceMIDIEvent`. |
| AU | `isProcessing()` наследовал состояние активности вместо отдельного состояния обработки. | Возвращается фактическое `m_processing`. |
| Общие аудиобуферы | Дублирование CLAP/VST3 и небезопасное разыменование отсутствующего канала. | Единое связывание шин учитывает null-каналы, sidechain, собственный scratch и точные маски тишины. |

## Переиспользование

- `plugins/Host/PluginAudioBuffers.hpp`: выделение и привязка planar-буферов для CLAP/VST3; безопасное обнуление выходов используется всеми четырьмя внешними адаптерами.
- `plugins/Host/PluginMidi.hpp`: один MIDI 1 кодек для VST1/2, MIDI-диалекта CLAP и AU. Проверяются канал, нота и конечность значения; note choke превращается в note off с нулевой скоростью.
- `Vst3Instance::reserveParameterChanges()`: одна настройка общего пула для обычной активации и офлайн-обновления метаданных.
- Проверки плагинов только с событиями и монотонного времени используют общие тестовые функции для CLAP и VST3.

Форматные правила активации, MIDI note expression, состояния и UI намеренно остаются внутри адаптеров. Совпадающий код объединён там, где совпадает и контракт.

- повторных уведомлений задержки при активации, сохранения других restart-флагов и последующих обновлений значений параметров;

## Воспроизведение

Из корня проекта в PowerShell:

```powershell
& .\build-windows\bin\plugin_probe.exe vst3 `
  'C:\Program Files\Common Files\VST3\Soundtheory\Gullfoss.vst3' `
  --host-cycles 20 --sample-rate 48000 --block-size 128

& .\build-windows\bin\plugin_probe.exe vst `
  'D:\Code\DAW\build-windows\plugins_test\DawTestVstShell.dll' `
  --blocks 2000 --block-size 1024 --dense-automation

& ctest --test-dir build-windows -C Release --output-on-failure --parallel 2 `
  -R '^(plugin_(contract|host|vst|vst3|midi|render_state|parallel_scan|scan)|offline_pipeline|render_integrity|engine_graph)_test$'
```

`plugin_probe` также выводит медиану, p99, максимум времени обработки и число вызовов дольше длительности блока. Эти измерения выполняются без realtime-планирования и аудиодрайвера; превышение в probe нельзя напрямую считать underrun устройства.

Контракты сверены с первичными источниками: [VST3 processing FAQ](https://steinbergmedia.github.io/vst3_dev_portal/pages/FAQ/Processing.html), [последовательность получения задержки VST3](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical%2BDocumentation/Workflow%2BDiagrams/Get%2BLatency%2BCall%2BSequence.html), [CLAP audio buffer contract](https://github.com/free-audio/clap/blob/main/include/clap/audio-buffer.h). В частности, CLAP `constant_mask` — подсказка; заполнение всех отсчётов буфера сохраняется.
