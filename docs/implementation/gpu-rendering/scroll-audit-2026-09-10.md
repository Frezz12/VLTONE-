# Проверка плавности GPU-интерфейса — 10 сентября 2026

Проверен проект «Стекла.vlt» на Apple M1, macOS 26.5.1, Qt 6.11.2,
Metal, Retina DPR 2, экран 60 Гц. Исправлены лишняя инвалидизация сцены,
дублирование планировщиков кадров и избыточная обработка примитивов.
Экспериментальный режим GPU сохранён; полная миграция рабочего пространства
из [основного плана](README.md) ещё не завершена.

Исходный пакет содержит 16 дорожек, 12 аудиоклипов и 37 описаний эффектов.
Использовалась отдельная копия с изолированными настройками и recovery.
SHA-256 всех 48 файлов оригинала совпал после проверки. В репозиторий
не добавлены аудио, состояния плагинов или содержимое проекта.

## Исправленные причины

| Before | After | Why |
|---|---|---|
| `SceneItem` безусловно вызывал `setMatrix` для каждого слоя, включая неподвижные панели | Матрица устанавливается только при изменении | Повторная установка помечала поддеревья изменёнными и уничтожала пользу сохранённых групп отрисовки |
| У каждого QWidget был отдельный узел отсечения | Он остаётся только там, где геометрия может выйти за границы | Лишние области отсечения мешали объединению отрисовки соседних элементов; нужное отсечение, включая фигурное, сохранено |
| Мелкие текстуры существовали отдельно | Используется атлас Qt с преобразованием UV к его подпрямоугольнику | Меньше переключений текстур; качество и DPI не меняются |
| Текст повторно вычислял границы; прямоугольные изображения и заливки проходили через контуры и триангуляцию | Границы текста кэшируются вместе с изображением; простые прямоугольники используют готовые треугольники и прямоугольное отсечение | Уменьшены расходы GUI-потока; сложные контуры сохраняют прежний путь |
| Кадр проходил через QWidgetWindow, paint, нулевой таймер захвата и отдельный цикл Quick | Quick вызывает FrameTimer, передаёт накопленную область изменений и записывает сцену перед синхронизацией этого кадра | Убрано промежуточное ожидание, сохраняется последнее состояние ввода; неподвижное окно не запускает непрерывный рендер |
| Перемещение слоя само по себе помечало его содержимое изменённым | Перемещение и изменение порядка обновляют размещение слоя | Геометрия неподвижного относительно панели содержимого может сохраняться |

Поток аудио не вызывает графические API и не ждёт новый планировщик.
FrameTimer и запись сцены получают общую временную оценку транспорта.
При удалении/сбое GPU-поверхности планировщик восстанавливает QWidget-путь,
включая ожидающие изменения. Дополнительное сглаживание жестов не введено.

## Сравнение двух GPU-сборок

Сравнивались исходный GPU-код на начало проверки и оптимизированный код.
Обе сборки использовали одинаковый новый тест полного окна и ввод через
нативную Quick-поверхность. Прокрутка: 1800 пикселей в каждую сторону,
полный цикл 1,2 с, события каждые 8 мс. Прогрев — 2 цикла, замер —
7–7,4 с по фактическим монотонным часам. Запуски последовательные, без сборки
или других тестов одновременно; сторонние приложения пользователя не закрывались.

CPU ниже — сумма CPU-времени GUI и потока рендера, делённая на число кадров.
Это расход двух потоков, а не задержка кадра. Во всех вариантах получено
59,86–60,00 кадров/с.

| Сценарий | CPU до, мс/кадр | CPU после, мс/кадр | Снижение | p99 интервала передачи кадров, до → после |
|---|---:|---:|---:|---:|
| Микшер открыт, воспроизведение остановлено | 15,20 | 9,37 | 38,4% | 19,60 → 20,58 мс |
| Микшер скрыт, воспроизведение остановлено | 12,55 | 8,08 | 35,6% | 19,26 → 18,95 мс |
| Микшер скрыт, тестовый аудиобуфер 32 | 18,39 | 13,06 | 29,0% | 20,14 → 20,30 мс |
| Микшер скрыт, тестовый аудиобуфер 512 | 15,99 | 11,10 | 30,6% | 19,44 → 19,32 мс |

С открытым микшером p95 синхронизации сцены снизился с 1,246 до 0,140 мс,
p95 подготовки — с 2,516 до 1,998 мс. Среднее ожидание от ввода до начала
записи Timeline в сопоставимых финальных запусках снизилось с 13,72 до
11,66 мс; при буфере 32 — с 13,68 до 10,44 мс. Ранние диагностические
прогоны давали другие абсолютные значения; они не включены в эту таблицу.

В аудиовариантах обрабатывается загруженный проект с доступными плагинами
через настоящий код колбэка и синтетическую доставку блоков, без открытия
звукового устройства. При 32 было 5 превышений бюджета из 11015 колбэков
до изменений и 2 из 10723 после. При 512 превышений не было в обеих сборках.
Это не счётчик аппаратных xruns и не подтверждение длительной записи.

## Что остаётся ограничением

Редкие длинные интервалы не устранены полностью: в финальном парном прогоне
при 32 максимальный интервал передачи кадра составил 34,93 мс. p99 почти
не изменился. Экономия CPU подтверждена; гарантировать отсутствие любых
потерь кадров по этим коротким запускам нельзя.

Добавлена отключённая по умолчанию диагностика `VLT_GPU_TIMESTAMPS=1`.
Она читает время ранее завершённого GPU-кадра без ожидания и без чтения
изображения обратно на CPU. В отдельном прогоне при 32 p95 GPU-времени
составил 2,273 мс, максимум — 2,436 мс; длинных интервалов и превышений
бюджета колбэка в том прогоне не было. В этом сценарии вычисления GPU
укладываются в бюджет 16,67 мс. Редкие ожидания драйвера/вытеснение потоков
требуют системной трассировки: точный источник каждого выброса не установлен.

`frameSwapped` обозначает передачу кадра для показа. Физическое представление
на экране, фазовая ошибка относительно слышимого звука, Windows/D3D11,
другие мониторы и 30-минутная аппаратная запись этим тестом не проверены.
GPU timestamps могут относиться к кадру несколькими позициями раньше;
их нельзя использовать как время показа текущего кадра.

В адаптере остаётся подготовка изменённых сеток, подписей и нот на GUI-потоке.
Полностью независимые Quick-редакторы и перенос видео/веб-фона остаются
отдельными этапами. В журнале загрузки также есть предупреждения Waves о
повторных Objective-C классах разных установленных версий; связь с просадками
прокрутки не установлена, сторонние установки не изменялись.

## Проверка и воспроизведение

Пройдены 9 регрессионных тестов: GPU-сцена и fallback, планировщик кадров,
профили качества, аудиочасы, граф движка, контроллер, CPU/GPU waveform.
Нативная проверка Metal проверяет пиксели, передачу ввода, изменение отсечения,
сохранение неизменённого изображения, остановку рендера в покое и fallback.
Проверены координаты/UV при смене transform и clip, восстановление painter
state, удаление планировщика с ожидающим кадром. Оригинал проекта не изменён.

```sh
# Использовать копию пакета, отдельные prefs и recovery.
VLT_GPU_WORKSPACE=1 \
DAW_PREF_DIR=/tmp/vlt-scroll-prefs DAW_RECOVERY_ROOT=/tmp/vlt-scroll-recovery \
VLT_UI_PROFILE=/tmp/vlt-scroll.json \
build/bin/VLTONE --project-scroll-check '/path/to/project-copy.vlt'
```

Дополнительно: `VLT_SCROLL_HIDE_MIXER=1`, `VLT_SCROLL_AUDIO_BLOCK=32` или
`512`, `VLT_SCROLL_MS=7200`, `VLT_SCROLL_DISTANCE=1800`.
`VLT_GPU_TIMESTAMPS=1` включает отдельную GPU-диагностику. Обычные сохранённые
настройки пользователя тестовый режим не использует.
