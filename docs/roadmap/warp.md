# Warp — развитие после помощника ритма

Название продукта и поле проекта остаются **Warp**. Интерфейс, помощник с
предпрослушиванием, Swing и Groove образуют текущий этап. Следующие возможности
не включены в него и не должны объявляться доступными в интерфейсе.

## 1. Сохранение атак и качество растяжения

Подготовить корпус mono/stereo: барабаны, вокал, бас, полифония, тихие атаки,
реверберация и темп с дрейфом. Сравнить действующие режимы с защитой атаки внутри
сегмента: измерять смещение onset, изменение спектра и высоты, межканальную фазу,
скачки на границах и нагрузку. Провести слепое прослушивание; включать новый режим
по умолчанию только при подтверждённом улучшении. Не увеличивать задержку ручного
редактирования и не переносить подготовку ресурсов в аудиопоток.

## 2. Group Warp

Связанные микрофонные записи получают общие целевые позиции и согласованные
исходные якоря. Проектировать общий граф временных преобразований группы,
транзакцию Undo и политику конфликтующих блокировок. Проверять моносовместимость,
фазу overhead/close-mic, копирование, split/trim, сохранение и offline render.
Групповое редактирование разрешать только после этих проверок.

## 3. Align to Reference

Использовать выбранный аудио- или MIDI-референс вместо равномерной сетки.
Сопоставление должно учитывать пропущенные и дополнительные атаки, пределы
растяжения и музыкальные фразы. Показывать уверенность каждого соответствия;
неоднозначные пары оставлять на рассмотрение пользователя. Сохранить общий
процесс: предложение → До/После → Применить/Отмена.

## 4. Более точный анализ

Калибровать confidence на размеченном корпусе отдельно для типов материала,
показывать дрейф темпа и альтернативные метрические интерпретации. Оценивать
плотность ложных атак и пропуски, а не только среднюю ошибку BPM. Рассматривать
локальные нейросетевые модели лишь после сравнения с DSP по качеству, времени,
памяти и воспроизводимости. Ошибка модели не должна лишать ручного редактирования.

## 5. Проект и совместная работа

Для облака нужны версия схемы карт, согласованные команды маркеров, устойчивые ID,
конфликты групповых операций и одинаковый render-cache на клиентах. До появления
этого протокола оставить явную блокировку публикации проектов с картами Warp,
включая историю запечённого аудио. Нельзя молча удалять неподдерживаемые карты.

Для каждого этапа: профильные DSP/controller/Qt-тесты, измерение callback allocations
и UI paint cost, проверка RU/EN и DPI, stage-сборка и контроль runtime dependencies.
